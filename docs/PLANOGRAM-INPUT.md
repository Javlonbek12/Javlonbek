# Планограммы: описание предметной области

Исходное описание, с которого начинался этап 7 (составлено по реальным планограммам заказчика: проект «ESSE Change 1», повышение цен, сентябрь 2026; сами примеры в репозиторий не кладутся). Как устроено сейчас — `docs/DECISIONS.md` (записи «Этап 7» и «После этапа 8» про планограммы, оборудование, шелфтокеры). Ответы на вопросы раздела 7 — в конце файла.

На сервер загружена библиотека из презентации «planogram_price_change_updated_02Nov2026»: 8 типов дисплеев, модули, LEGO, POG, 42 SKU с картинками, POSM, шелфтокеры.

## 1. Что такое планограмма у заказчика

Схема раскладки сигаретных пачек на торговом оборудовании в точке продаж. Один слайд PowerPoint = одна единица оборудования. На слайде:
- картинка оборудования с полками;
- в каждой ячейке (слоте) — картинка пачки (один facing);
- **под каждым facing — ценник** (например `31 000`, `28 000`, `21 000`, `18 000`; это цена в сумах, формат «XX 000»); у некоторых SKU вместо/рядом с ценой — бейдж `1mg` или `2mg`. На полке со **шелфтокером** (полоса на краю полки) ценник стоит в самой полосе — тёмная плашка с белой ценой;
- на пачках-новинках — стикер `YANGI` («новинка»); в приложении он вверху пачки, на предупреждении о вреде (дизайн пачки внизу);
- POSM-элементы: хедер над полками, промо-баннеры, стикеры, занимающие часть полки;
- рядом со схемой — ручные пометки: пачки, которые нужно убрать (`delete`), переместить (`Вниз`), и выноски с ценами.

Сейчас всё это делается вручную в PowerPoint. При повышении цен приходится править ценники на каждом слайде, при вводе новинки — передвигать пачки на каждом слайде.

## 2. Типы оборудования (из примеров)

### 2.1 Дисплеи (вертикальные стойки с полками)
Называются `Display <размер> <канал>`: размеры **XL, L, M, C, S**, каналы **POSI, MW/DG, DG, MW** **(уточнить расшифровку каналов)**.

Общий состав сверху вниз (Display L POSI):
1. Хедер (баннер кампании, напр. «B1RINCHILAR DAVRI / 1MG»).
2. Полка новинок: стикер `ENDI 1MG` занимает ~2 слота слева, далее 8 facing ESSE с бейджами `YANGI`. Ценники: `28 000`, `1mg`, `21 000`…
3. Промо-баннер на всю ширину (напр. «QIROL QAYTDI» для PINE) + зелёная подложка.
4. Полка PINE/Blooming: стикер `KAPSULALI YASHIL` (~2 слота) + 8 facing (PINE Green, PINE Blue, PINE KS, Blooming…). Ценники `18 000` / `18 ming`.
5. Пустая полка с POSM «BU YERDA» (под будущую выкладку) + цветная полоса.
6. Полка ESSE основной линейки: 10 facing (ESSE Special Gold, Change, DEM, GS, …). Ценники `31 000`, `26 000`, `24 000`, `22 000`, `21 000`.
7. Полка BOHEM: 10 facing с крупными буквами **L / C / F** на пачках **(уточнить: что означают L, C, F — вероятно варианты BOHEM Cigar)**. Ценники `24 000`, `21 000`, `20 000`, бейдж `1mg`.
8. Нижняя полка: 10 facing (Simple `2mg`, Blooming). Ценники `20 000`, `18 ming`.

Количество слотов на полке зависит от размера дисплея: **XL ~12, L ~10, M ~6, C ~10 (2 колонки-блока рядом), S — 2 полки по 10** **(уточнить точные числа и ширину полок в мм)**.

Display S MW — горизонтальный: две полки по 10 слотов + вертикальный хедер справа.

### 2.2 Модульное оборудование
Прямоугольные модули `Размер <колонки>*<ряды>` — **9×2, 9×1, 6×3, 3×2, 3×6**. Слот = одна пачка. Внутри модуля слоты сгруппированы по 3 (визуальные секции). Ценник под каждым facing. Хедера нет.

### 2.3 LEGO
Модульные стойки нестандартной формы: **LEGO на 21 слот** (3 ряда по 9, но верхний ряд только 3 слота в центре — ступенчатая форма) и **LEGO на 27 слотов** (3×9). Геометрия должна поддерживать неполные ряды со смещением.

### 2.4 POG (один ряд)
`POG Планограмма MINI` — 18 facing в один ряд; `POG MAX` — ~23 facing в один ряд (в MAX добавлены дубли facing у приоритетных SKU). Отдельно показан список **«Обязательные 9 SKU из 18, которые должны быть выставлены в переднем ряду»** — это правило валидации.

## 4. POSM-элементы (из примеров)
- **Хедер** (над полками): «B1RINCHILAR DAVRI / ВРЕМЯ ПЕРВЫХ / 1MG» — горизонтальный (дисплеи XL/L/M/C) или вертикальный (Display S, справа).
- **Промо-баннер на полку**: «QIROL QAYTDI» (PINE, лев) — занимает всю полку.
- **Стикеры в слотах**: `ENDI 1MG` (~2 слота), `KAPSULALI YASHIL` (~2 слота), `BU YERDA` (~2 слота, на пустой полке).
- **Бейджи на пачках**: `YANGI` (вверху пачки), `1mg`, `2mg` (на ценнике).
- **Цветные полосы на краю полок — шелфтокеры** (тип POSM «Шелфтокер»): на каких полках они есть, задаётся в модели оборудования; ценники стоят в полосе.
- **Combo Box** — POSM на несколько полок (поле «Сколько полок занимает (вниз)»): стоит на нижней из них, шелфтокер за ним не идёт.
- Примечания к подсветке: «подсветка в Комбо Бокс должна быть зелёная, по периметру оборудования — голубая» — хранить как текстовое примечание к планограмме.

## 5. Правила раскладки (наблюдаемые; заказчик подтвердит)
1. Обязательный набор SKU (напр. 9 из 18) должен присутствовать в переднем ряду.
2. Бренд-блоки: ESSE основной ряд → BOHEM → PINE/Blooming → Simple; новинки ESSE — на верхней полке со стикером `ENDI 1MG`.
3. Новинки отмечаются `YANGI`; у 1mg-вариантов бейдж `1mg` на ценнике.
4. Приоритетные SKU получают несколько facing подряд (в POG MAX — дубли).
5. Под каждым facing — ценник из актуального прайс-листа; `18 000` отображается как `18 ming` для PINE/Blooming **(уточнить: это стиль ценника для определённых брендов или просто два варианта оформления)**.
6. При изменении раскладки формируется лист изменений: что убрать (`delete`), что переместить (`Вниз`), что добавить, какие цены поменялись.

## 6. Сценарии использования (что должно стать быстрым)
1. **Повышение цен:** загрузить новый прайс-лист → все активные планограммы получают новые ценники → пакетный экспорт PPTX для рассылки.
2. **Новинка:** добавить SKU с картинкой → указать, на какую полку/позицию ставить на каждом типе оборудования → система создаёт новые версии всех планограмм с листом изменений.
3. **Новый проект/кампания:** взять шаблон дисплея, заменить хедер и промо-баннер, утвердить, разослать.
4. **Адаптация под размер:** есть Display L — нужно сделать M и C с теми же правилами.
5. **Для мерчендайзера:** открыть планограмму по ссылке с телефона, видеть действующую схему и список изменений (сравнение «было/стало» — внутри приложения, `/planograms/[id]/compare`).
