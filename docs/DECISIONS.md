- 2026-10-02 — Этап 0 — Тексты интерфейса: словарь `lib/i18n/ru.ts` и функция `t("раздел.ключ")`; ключи проверяются TypeScript-ом.
- 2026-10-02 — Этап 0 — Переменные окружения проверяются zod-схемой в `lib/env.ts`; обязательна пока только `DATABASE_URL`, остальные станут обязательными на своих этапах.
- 2026-10-02 — Этап 0 — Service worker (`public/sw.js`) написан вручную без библиотек; статика — «сначала кэш». Включается только в production-сборке, чтобы не мешать разработке.
- 2026-10-02 — Этап 0 — Иконки PWA — заглушки (буква «A»), генерируются скриптом `scripts/generate-placeholder-icons.mjs`; заменить на настоящие позже.
- 2026-10-02 — Этап 0 — Prettier не форматирует Markdown-файлы (`*.md`), чтобы не менять SPEC.md и документы заказчика.
- 2026-10-02 — Этап 0 — Whisper в dev docker-compose пока не добавлен (в SPEC он опционален); появится на этапе 3 вместе с распознаванием речи.
- 2026-10-02 — Этап 0 — `npm run lint` = ESLint + проверка форматирования Prettier; `npm run format` исправляет форматирование.
- 2026-10-02 — Этап 1 — Сессия — подписанная (HMAC, `SESSION_SECRET`) httpOnly-cookie на 30 дней, без таблицы сессий (в SPEC нет модели Session). Выход = удаление cookie; «выйти на всех устройствах» = смена `SESSION_SECRET`.

- 2026-10-02 — Этап 1 — Регистрация возможна и с сайта (виджет Telegram), и через бота (`/start <код приглашения>`); обе дороги идут через одну функцию `loginWithTelegram`.
- 2026-10-02 — Этап 1 — Права: OWNER приглашает MANAGER/MEMBER, MANAGER — только MEMBER, MEMBER — никого; роли меняет только OWNER; OWNER — всегда один, роль OWNER нельзя ни выдать, ни снять.
- 2026-10-02 — Этап 1 — Приглашение: одноразовый код (12 символов), срок 7 дней, можно отменить; используется атомарно (два человека не займут одно приглашение).
- 2026-10-02 — Этап 1 — Связь «руководитель → его команда» пока не хранится (появится на этапе 6 в карточках); список «Команда» видят все участники, приглашения — OWNER (все) и MANAGER (свои).
- 2026-10-02 — Этап 1 — Бот может писать человеку, только если тот нажал `/start`; поэтому у пользователя хранится `botChatId`, а на главной странице есть подсказка «подключите бота».
- 2026-10-02 — Этап 1 — Тихие часы: в это время уведомление сохраняется в приложении, но в Telegram не отправляется. Отложенная отправка после окончания тихих часов — на этапе 4 (планировщик).
- 2026-10-02 — Этап 1 — Типы уведомлений: `test` (отключить нельзя), `invite_accepted`, `role_changed`. Новые типы добавляются в `modules/core/notifications/types.ts`.
- 2026-10-02 — Этап 1 — Изменения из UI делаются через Server Actions Next.js (каждое действие проверяет пользователя и права в сервисе); API-роуты — для входа/выхода, webhook бота и health.
- 2026-10-02 — Этап 1 — Rate limit — простой счётчик в памяти процесса (вход: 10/мин на IP, действия: 30/мин на пользователя, бот: 20 сообщений/мин). Достаточно для одного сервера.
- 2026-10-02 — Этап 1 — Webhook бота сначала сам проверяет секретный заголовок, и только потом передаёт запрос grammY.
- 2026-10-02 — Этап 1 — Service worker больше не кэширует страницы (в них личные данные): без сети показывается страница /offline.
- 2026-10-02 — Этап 1 — Тесты используют отдельную базу `assistant_test` (имя обязано оканчиваться на `_test`, иначе тесты не запустятся); тестовые файлы выполняются по очереди. Telegram в тестах всегда подменён заглушкой.
- 2026-10-02 — Этап 1 — Простые UI-компоненты (Card, Input, Label, Badge, NativeSelect) написаны в стиле shadcn/ui вручную; для выбора используется обычный `<select>` — удобнее на телефоне.
