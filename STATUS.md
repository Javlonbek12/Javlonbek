## Этап 0 — Каркас проекта

### Что сделано
- Next.js 16 + TypeScript + Tailwind CSS 4 + shadcn/ui (кнопка `Button`, тема).
- Пустая страница «Assistant» на русском, тексты интерфейса — в словаре `lib/i18n/ru.ts`.
- Prisma 7 + PostgreSQL 16; `docker-compose.yml` поднимает базу для разработки; пустая схема и seed-скрипт.
- Проверка переменных окружения (`lib/env.ts`), `.env.example` с комментариями на русском.
- `/api/health` — проверка, что приложение и база работают.
- PWA: manifest, иконки-заглушки, service worker (страница открывается без интернета).
- Vitest + Testing Library, ESLint + Prettier, typecheck. Тесты: 9 штук (i18n, env, главная страница, интеграционный тест API с базой).
- GitHub Actions: lint + typecheck + test + build на каждый push.
- README.md, STATUS.md, docs/DECISIONS.md.

### Что проверить вручную
См. README: «Первый запуск».

### Отложено / открытые вопросы
- `npm audit` показывает 4 уязвимости «high» в зависимостях инструмента Prisma (пакет `mysql2`, который мы не используем, только при разработке). На работу приложения не влияет; обновим, когда Prisma выпустит исправление.
- Иконки PWA — заглушки, нужны настоящие (логотип).
- Вопросы по планограммам из `docs/PLANOGRAM-INPUT.md` (раздел 7) — нужны к этапу 7.

## Этап 1 — Ядро: вход, роли, бот-скелет, уведомления

### Что сделано
- Таблицы: User, Invite, Notification, UserSettings, ActivityLog (миграция `core`).
- Вход через Telegram Login Widget (с проверкой подписи), сессия в httpOnly-cookie. Первый вошедший — OWNER, остальные — только по приглашению.
- «Вход для разработки» для проверки на своём компьютере без домена.
- Приглашения: ссылка на сайт и ссылка на бота, одноразовые, 7 дней, отмена. Страница «Команда»: участники, роли, смена роли (OWNER), приглашения.
- Бот (grammY): `/start` (привязка или регистрация по коду), `/help`; режимы long polling (`npm run bot:dev`) и webhook (`/api/telegram/webhook`, `npm run bot:set-webhook`).
- Сервис `notify()`: уведомление в приложении + в Telegram; страница уведомлений (счётчик непрочитанных, «прочитано»), настройки (Telegram вкл/выкл, тихие часы, типы уведомлений, часовой пояс), тестовое уведомление.
- Меню: снизу на телефоне, слева на компьютере; пункты берутся из реестра модулей с учётом роли.
- Журнал действий: вход новых людей, приглашения, смена ролей.
- Тесты: 79 (роли и права, приглашения, подпись Telegram, сессии, тихие часы, уведомления, бот, API входа/выхода/webhook, сквозной сценарий этапа).

### Что проверить вручную
См. README: «Подключение Telegram-бота», «Как пригласить сотрудника».

### Отложено / открытые вопросы
- Проверка с настоящим Telegram (вход виджетом, сообщения от бота) — нужен токен бота; кнопка входа на сайте заработает только на домене (этап 8).
- Отключение/удаление сотрудника из команды — в SPEC не описано; можно добавить, если нужно.
- Отправка уведомлений после окончания «тихих часов» — на этапе 4.

## Этап 2 — Задачи

### Что сделано
- Таблицы: Task, TaskDependency, Plan, Comment, TaskAttachment (миграция `tasks`).
- Статусы с согласованием (черновик → на утверждении → утверждена → в работе → на проверке → выполнена, плюс «отменена»); личные задачи без согласования и видны только автору.
- Связи «блокирует / зависит от»: нельзя закрыть задачу при открытых блокирующих, защита от замкнутых цепочек, вся цепочка в карточке, подсветка заблокированных.
- Планы год → месяц → неделя с процентом выполнения (с учётом вложенных планов).
- Экраны: «Сегодня», список с фильтрами, канбан с перетаскиванием, календарь (месяц/неделя/день), таймлайн со стрелками связей, планы, карточка задачи (статусы, связи, вложения, комментарии, история).
- Уведомления: задача ждёт утверждения, вам назначена задача, задача на проверке / принята / возвращена / отменена, новый комментарий.
- Тесты: 151 (переходы статусов, права и видимость, блокировки и циклы, планы, календарь, таймлайн, фильтры, уведомления, полный цикл задачи, API вложений).

### Что проверить вручную
См. README: «Как работают задачи».

### Отложено / открытые вопросы
- Редактирование и удаление планов; перенос задачи между личной и командной.
- Задачи из бота (текст и голос) — этап 3; напоминания о сроках — этап 4.
- «Руководитель видит только свою команду» — после появления связи «руководитель» на этапе 6.

## Этап 3 — Бот: задачи текстом и голосом

### Что сделано
- Модуль ИИ (`modules/ai`): `extractTasks` и `interpretCommand` с проверкой ответа (zod), повтором, учётом токенов (`AiUsage`) и дневным лимитом; сводка расхода для OWNER в «Настройках».
- Распознавание речи (`modules/stt`): свой Whisper, внешний сервис, заглушка — выбор через `STT_PROVIDER`.
- Бот: текст или голосовое → карточка подтверждения (✅ Сохранить / ✏️ Изменить название, срок, исполнителя / ❌ Отмена), несколько задач в одной карточке, уточнение исполнителя кнопками.
- Команды `/today`, `/week`, `/overdue`, `/pending`; фразы «что у меня сегодня», «перенеси X на четверг», «закрой задачу X».
- Утверждение и приёмка задач кнопками прямо из уведомления в Telegram.
- Тесты: 224 (18 фраз на трёх «языках», карточка и её редактирование, голос, команды, кнопки, работа самого бота с Telegram API на подставных данных). Живой набор `npm run test:ai` — 25 проверок с настоящим Claude.

### Что проверить вручную
См. отчёт в чате (после этапа 8 — общий чеклист).

### Отложено / открытые вопросы
- Живой прогон с настоящим Claude не выполнен в среде разработки (нет ключа). Нужно: вписать `ANTHROPIC_API_KEY` в `.env` и запустить `npm run test:ai`.
- Проверка с настоящим Telegram — после получения токена бота (локально `npm run bot:dev`) или на сервере (этап 8).

## Этап 4 — Напоминания и дайджесты

### Что сделано
- Фоновый процесс `npm run worker` (pg-boss, запуск раз в минуту).
- Утренний дайджест (время настраивается, по умолчанию 08:30, текст пишет ИИ, без ИИ — шаблон), напоминание за день до срока, уведомление о просрочке (исполнителю и постановщику), пятничный итог по команде для руководителей.
- «Тихие часы» теперь откладывают отправку в Telegram до утра, а не теряют её.
- Новые типы уведомлений можно отключить в настройках.
- Тесты: разные часовые пояса (Ташкент, Москва, Нью-Йорк), отсутствие дублей (в т.ч. при параллельных запусках), тихие часы, запуск pg-boss.

### Отложено
- (сделано на этапе 5) Напоминание за 15 минут до встречи.

## Этап 5 — Встречи и минутки

### Что сделано
- Таблицы Meeting, MeetingParticipant, MeetingNotes; задача может ссылаться на встречу.
- Встречи: создание (участники, повестка, ссылка на Zoom/Meet), еженедельные повторения, изменение, удаление одной или «этой и следующих»; приглашение участникам.
- Встречи в общем календаре (фиолетовым), на экране «Сегодня», отдельный раздел «Встречи».
- Минутки на сайте или голосом в боте (`/notes`) → ИИ находит задачи → подтверждение → задачи со ссылкой на встречу.
- Напоминание за 15 минут до встречи.
- Тесты: повторения и часовые пояса, права доступа, 3 примера минуток (русский, узбекский, «без задач»), путь через бота, напоминание без дублей. Живой набор `npm run test:ai` дополнен минутками.

## Этап 6 — Карточки сотрудников

### Что сделано
- Профиль сотрудника: должность, зона ответственности, контакты, дата начала, руководитель и подчинённые.
- Статистика: активные, просроченные, «вовремя» за 30/90 дней, средняя длительность, мини-график загрузки по неделям.
- Приватные заметки руководителя (сильные стороны, зоны роста, 1:1, цели развития) — только OWNER и непосредственный руководитель.
- Экран «Команда»: сетка карточек с загрузкой, поиск, фильтры «Мои подчинённые» и «С просрочками»; управление ролью и тестовое уведомление — в карточке.
- Тесты: расчёт статистики, права на заметки (сотрудник, коллега, другой руководитель не видят; смена руководителя), права на профиль, защита от «круговых» подчинений.

## Этап 7 — Планограммы

### Что сделано
- Справочники: оборудование (конструктор полок с предпросмотром; 5 типов из ТЗ уже заведены), SKU (картинка, бренд, формат, бейджи, новинка, обязательный, вид ценника), POSM (хедер, баннер, стикер), прайс-листы.
- Импорт SKU и цен из Excel/CSV; при новом прайс-листе — предпросмотр «что изменится» и создание новых версий одним нажатием.
- Редактор раскладки: перетаскивание или «кисть», выбор нескольких ячеек, копирование полки, бейджи, отмена/повтор, проверка правил «на лету».
- Создание с нуля, из шаблона или автозаполнением по правилам; шаблоны; адаптация под другое оборудование.
- Статусы, версии, история, сравнение «было/стало» с подсветкой и текстом изменений.
- Экспорт PPTX (несколько планограмм проекта — один файл), PDF, PNG; отправка картинки и ссылки в Telegram выбранным сотрудникам.
- Публичная ссылка для мерчендайзеров без входа и версия для печати.
- Массовые операции: заменить SKU везде, добавить новинку во все планограммы оборудования, утвердить все ожидающие.
- Тесты: геометрия, раскладка, правила, автозаполнение, замены и адаптация, цены, сравнение версий, отрисовка, редактор; интеграционные — весь цикл от создания до экспорта, права, прайс-листы, массовые операции, публичная ссылка.

### Что проверить вручную
См. отчёт в чате (после этапа 8 — общий чеклист).

### Отложено / открытые вопросы
- Реальный список SKU, картинки пачек и фирменный шаблон PPTX — от заказчика (сейчас тестовые данные и простые слайды).
- «Предложить раскладку ИИ» по описанию не делал: автозаполнение по правилам закрывает основной сценарий; можно добавить позже.
- Порядок брендов по умолчанию выключен — включается в «Правилах проверки» конкретной планограммы.

## Этап 8 — Деплой на VPS и эксплуатация

### Что сделано
- `Dockerfile` (сборка в два шага) и `docker-compose.prod.yml`: база, миграции, сайт, планировщик, сторож, распознавание голоса (по желанию), Caddy с HTTPS.
- `docs/SETUP-SERVER.md` — пошаговая установка на Ubuntu 24.04 для нетехнического человека; `docs/USER-GUIDE.md` — руководство сотрудника.
- Автообновление сервера из GitHub после зелёных проверок (`.github/workflows/server.yml`, `scripts/deploy.sh`); там же установка, состояние, журналы и бэкап сервера одной кнопкой.
- Ежедневные бэкапы с хранением 14 дней и восстановление (`scripts/backup.sh`, `scripts/restore.sh`).
- Сторож: сообщение владельцу в Telegram, если сайт, планировщик или бот перестали работать (и когда снова заработали).
- Проверено в среде разработки: образ собирается, вся связка поднимается с нуля, миграции применяются, `/api/health` отвечает через HTTPS, планировщик работает, бэкап → восстановление возвращает данные, кириллица в картинках рисуется.

### Что проверить вручную
См. общий чеклист в отчёте в чате.

### Отложено / открытые вопросы
- Установка на настоящий сервер с доменом, проверка настоящего бота и распознавания голоса — нужны сервер, домен и токен бота (в среде разработки нет выхода в Telegram и к модели распознавания).
- Бэкапы хранятся на том же сервере; копирование в облако (S3 и т.п.) — по желанию позже.
