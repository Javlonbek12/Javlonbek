# Assistant

Платформа «личный помощник + команда + рабочие утилиты». Полное техническое задание — в [SPEC.md](SPEC.md), текущий прогресс — в [STATUS.md](STATUS.md).

**Что осталось сделать и что нужно от владельца — [docs/NEXT-STEPS.md](docs/NEXT-STEPS.md).**
Рабочий сайт: https://5-182-33-60.sslip.io.

## Что нужно установить на компьютер

1. **Node.js 22** (или новее) — https://nodejs.org (кнопка «LTS»).
2. **Docker Desktop** — https://www.docker.com/products/docker-desktop (нужен, чтобы запустить базу данных одной командой).
3. **Git** — https://git-scm.com.

## Первый запуск (пошагово)

Все команды вводятся в терминале, в папке проекта.

1. Скачать проект:
   ```
   git clone https://github.com/Javlonbek12/Javlonbek.git
   cd Javlonbek
   ```
2. Создать файл настроек из образца:
   ```
   cp .env.example .env
   ```
   Откройте `.env` в любом текстовом редакторе и впишите в `SESSION_SECRET` любую случайную строку длиной от 32 символов (например, результат команды `openssl rand -hex 32`). Остальное для локального запуска можно не менять.
3. Установить зависимости (займёт пару минут):
   ```
   npm install
   ```
4. Запустить базу данных (Docker Desktop должен быть открыт):
   ```
   docker compose up -d
   ```
5. Применить миграции и тестовые данные:
   ```
   npm run db:migrate
   npm run db:seed
   ```
   До первого входа `db:seed` загружает только справочники планограмм (тестовые SKU, POSM, оборудование). Демо-планограммы появятся, если после первого входа запустить его ещё раз.
6. Запустить приложение:
   ```
   npm run dev
   ```
   Для напоминаний и дайджестов запустите в отдельном окне терминала фоновый процесс: `npm run worker`.

   Открыть в браузере http://localhost:3000 — появится страница входа. Пока Telegram-бот не настроен, используйте блок «Вход для разработки». **Первый вошедший становится Владельцем (OWNER).**

> Если вы запускали базу ещё на этапе 0, тестовой базы в ней нет. Создайте её один раз:
> `docker compose exec postgres createdb -U assistant assistant_test`

## Подключение Telegram-бота (на своём компьютере)

1. В Telegram откройте @BotFather → `/newbot` → придумайте имя → получите **токен**.
2. Впишите в `.env`: `TELEGRAM_BOT_TOKEN=<токен>` и `TELEGRAM_BOT_USERNAME=<имя бота без @>`.
3. В отдельном окне терминала запустите бота: `npm run bot:dev` (приложение `npm run dev` должно работать параллельно).
4. Напишите боту `/start` — он привяжется к вашему аккаунту, и уведомления начнут приходить в Telegram.

Кнопка «Войти через Telegram» на сайте работает только на настоящем домене (его указывают боту в @BotFather командой `/setdomain`), поэтому на `localhost` она не появится — это нормально. На сервере (этап 8) она заработает.

## Как пользоваться ботом

- Напишите или наговорите голосом: «Азизу подготовить отчёт до пятницы, а мне позвонить дистрибьютору завтра». Бот покажет карточку с маршрутом каждой задачи («↪ сразу», «↪ на утверждение: …») — проверьте и нажмите ✅ Сохранить (или ✏️ Изменить).
- Задача себе — командная (её видит ваш руководитель). Личная — только если попросить: слово «личная» в сообщении или кнопка «🔒 Я (личная)» при выборе исполнителя.
- Понимает русский, узбекский (латиница и кириллица) и их смесь, а также «завтра», «в пятницу», «через неделю», «до конца месяца».
- Спросите: «что у меня сегодня», «перенеси отчёт на четверг», «закрой задачу отчёт» — или используйте команды `/today`, `/week`, `/overdue`, `/pending` (утвердить, принять работу, решить запрос на удаление), `/notes` (итоги встречи), `/content` (контент на сегодня).
- Чтобы бот понимал свободный текст, нужен ключ ИИ (`ANTHROPIC_API_KEY` в `.env`). Для голосовых — сервер распознавания (`STT_PROVIDER`, см. `.env.example`).
- Проверка ИИ на 18 примерах фраз: `npm run test:ai` (нужен ключ; несколько центов).

## Как пригласить сотрудника

1. Раздел **Команда** → «Новое приглашение» → выберите роль → «Создать приглашение».
2. Отправьте человеку ссылку (кнопка «Копировать») или ссылку на бота.
3. Приглашение одноразовое и действует 7 дней. Его можно отменить.

Остановить приложение: `Ctrl + C` в терминале. Остановить базу: `docker compose down` (данные сохраняются).

## Как работают задачи (коротко)

- **Командная задача** (по умолчанию, в том числе задача себе): кнопка «Создать», маршрут система строит сама по оргструктуре (маршрут v2, «утверждение по исключению»):
  - себе, своему подчинённому или коллеге своей команды — задача сразу у исполнителя;
  - руководителю — он сам решает, принять ли её; человеку другой команды — решает его руководитель;
  - галочка «Требует утверждения» или настройка «утверждать внутри команды» — задача ждёт решения.
  Решения ждут во вкладке «Ждут решения». Исполнитель берёт задачу в работу и сдаёт на проверку, результат принимает автор (задачу себе — ваш руководитель; у владельца она закрывается сразу).
- **Личная задача:** галочка «Личная задача» — видна только вам, без маршрута: «Создать и начать» → «Завершить».
- Задача открывается в панели справа: вкладки «Описание», «Работа» (шаги с ответственным и сроком), «Заметки» (общие, с оформлением), «Файлы», «Комментарии», «История»; метки, соисполнители, повтор (каждый день, неделю, месяц, год).
- Удалить свою задачу, в которой никто, кроме вас, ничего не делал, можно сразу; иначе — запросом руководителю. Удалённая командная задача 30 дней лежит в корзине (`/tasks/trash`, её видит владелец; срок — «Настройки → Роли и доступ»).
- Задачу нельзя закрыть, пока не закрыты задачи, от которых она зависит (раздел «Связи» в карточке).
- Загруженные файлы хранятся в папке `uploads/` (настройка `UPLOAD_DIR`).

## Как работают планограммы (коротко)

- Раздел «Планограммы»: вкладки «Шаблоны», «SKU», «POSM», «Прайс-листы» — справочники; «Оборудование» ведёт в раздел «Оборудование → Модели» (полки, шелфтокеры); «Массовые операции» — замены по всем планограммам.
- Новая планограмма → редактор (на компьютере) → «Отправить на утверждение» → руководитель или владелец «Утверждает» (нельзя, пока есть критичные нарушения правил).
- Утверждённую планограмму нельзя менять: «Новая версия» создаёт копию, после утверждения старая уходит в архив, а ссылка для мерчендайзеров сама показывает новую. Если из одной версии сделали две параллельные, вторую можно утвердить только с подтверждением (она не содержит изменений первой).
- Новые цены: «Прайс-листы» → загрузить Excel/CSV (колонки «код», «цена») или «Скачать шаблон с актуальными ценами» → посмотреть, что изменится → «Утвердить»: утверждённые планограммы получают новые версии (с критичными нарушениями — остаются черновиками), черновики переводятся на новый прайс-лист.
- На полке с шелфтокером ценники стоят в его полосе (тёмные), «YANGI» — вверху пачки.
- Экспорт: кнопки PPTX (каждая пачка, ценник и POSM — отдельный объект) / PDF / PNG и «3D-вид» в карточке планограммы; весь проект одним файлом — в списке, фильтр по проекту.

## Полезные команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Запуск в режиме разработки (http://localhost:3000) |
| `npm run build` / `npm start` | Сборка и запуск «боевой» версии |
| `npm test` | Все тесты (нужна запущенная база; тесты используют отдельную базу `assistant_test`) |
| `npm run lint` | Проверка кода и форматирования |
| `npm run format` | Автоматически исправить форматирование |
| `npm run typecheck` | Проверка типов TypeScript |
| `npm run db:migrate` | Применить изменения схемы базы данных |
| `npm run db:seed` | Заполнить базу тестовыми данными |
| `npm run worker` | Фоновый процесс: дайджесты и напоминания (раз в минуту) |
| `npm run watchdog` | Сторож: сообщает владельцу в Telegram, если сайт, планировщик или бот не работают |
| `npm run bot:dev` | Запустить Telegram-бота на своём компьютере (long polling) |
| `npm run bot:set-webhook` | На сервере: подключить бота через webhook |
| `http://localhost:3000/api/health` | Проверка, что приложение и база работают |

## Структура проекта

```
app/          страницы и API (Next.js)
components/   общие UI-компоненты (shadcn/ui)
lib/          общие утилиты: i18n (тексты интерфейса), env, подключение к базе
modules/      модули платформы: core (вход, роли и доступ, приглашения, уведомления), tasks, meetings, team, org (оргструктура),
              projects, planograms, content (контент-план), distribution (распределение POSM, оборудование),
              connect (аналитика Connect), reports, scheduler, ai, bot (Telegram), stt (голос), ops (отчёт usage)
prisma/       схема базы данных, миграции, тестовые данные
docs/         решения (DECISIONS.md), установка на сервер (SETUP-SERVER.md), руководство сотрудника (USER-GUIDE.md)
deploy/       настройки сервера: Caddy (HTTPS), шрифты
scripts/      обновление сервера, бэкап и восстановление, webhook бота, сторож, загрузка данных
              (data-load, org-import, project-import/create, team, usage, demo-data)
public/       иконки, service worker
assets/       шрифты для PDF (DejaVu, свободная лицензия)
tests/        интеграционные тесты (с настоящей базой данных)
```

## Проверки на GitHub

При каждом push GitHub Actions автоматически запускает lint, typecheck, тесты и сборку (файл `.github/workflows/ci.yml`). Результат виден на вкладке **Actions** репозитория.

## Установка на сервер

Пошаговая инструкция — [`docs/SETUP-SERVER.md`](docs/SETUP-SERVER.md): Ubuntu 24.04, Docker, домен с HTTPS,
бот, ежедневные бэкапы, мониторинг. После настройки секретов `VPS_HOST`, `VPS_USER`, `VPS_SSH_KEY`
каждый push в `main` с зелёными проверками сам обновляет сервер. Остальное — кнопкой Actions → Server (`.github/workflows/server.yml`): установка, состояние, журналы, перезапуск, бэкап и `backup-export` (скачать архив к себе), `usage` (кто работает в приложении), `team-check` / `team-fix` (люди, роли, места, удаление сотрудника), `org-import` / `org-replace`, `project-import` / `project-create`, `data-key` / `data-load` (загрузка данных), `demo-add` / `demo-remove`. Описание действий — в `docs/SETUP-SERVER.md`.

Руководство для сотрудников — [`docs/USER-GUIDE.md`](docs/USER-GUIDE.md).
